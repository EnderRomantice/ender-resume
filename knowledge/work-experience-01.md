# 公司与方向

42 是一家聚焦视障辅助、宠物智能与阿尔茨海默照护赛道的 AI 硬件初创公司。这段工作为 Beijing · Remote；我负责全栈开发与产品交付，重点是让 Agent 参与可交互的长任务协作、为工具执行补齐可靠性机制，以及将招聘判断接入有依据、可核查的业务流程。

# 我的角色

我担任全栈开发工程师 / 负责人，负责从需求拆解、产品与架构决策到工程实现和交付。最有代表性的产出是桌面多 Agent 工作台、TypeScript Agent Runtime，以及已上线招聘后台中的 Agent 工作流；此外也完成了协作服务、双语品牌与申请体验和社群运营工具。

# 解决的问题与产出

- 多 Agent 协作：针对长任务占用对话、用户难以在执行途中继续沟通的问题，设计并实现桌面 Agent 工作台，将即时沟通、任务规划与工具执行分工。任务在后台运行，支持并行 Worker、追加指令、取消、查看产物和结果汇报；工作台已交付 macOS / Windows Alpha 测试包。
- 执行可靠性：针对 Agent 并发工具调用、进程中断和数据库提交结果不明，自研 TypeScript Agent Runtime，提供会话内有序调度、工具并发与独占控制，以及持久化检查点对账。已有结果可补入会话记录，结果不确定的操作不会被自动重放，避免将故障恢复误处理为再次执行外部操作。
- 招聘 Agent：面向候选人材料分散、初筛和检索依赖人工的问题，在已上线的招聘后台中串联材料读取、候选人建档与自然语言筛选。评价按岗位层级、材料来源与证据充分度约束，服务端重算分数并设置证据不足时的分数上限，保留判断依据与工具记录，供招聘人员核查。

# 实现方式

- `42-agent-desktop`：由 Leader 负责即时沟通和任务协调，简单任务直接交给 Worker，复杂任务由 Planner 拆解后交给 Worker；规划与执行工具分离，后台任务持久化状态、事件与产物，支持执行中追加指令和取消。
- `42-agent`：提供可嵌入的 TypeScript 执行内核，将模型与工具调用纳入统一生命周期；会话内 FIFO、跨会话并发、工具并发上限与独占屏障共同约束执行，检查点覆盖会话、运行和工具结果。
- `42-admin`：搜索 Agent 通过工具调用串联候选人查询、标签和建档，建档后进入异步分析队列。PDF 优先提取文本，材料不充分时补充 OCR；评价输出采用结构化校验、服务端加权重算与证据分数上限，更新 AI 标签时保留人工标签。
- `42-agent-service`：承担组织、账号、消息与集中模型访问。配合桌面端实现持久化发件箱、幂等提交、事件游标回补和本地原子投影，处理断线重试与组织切换；这些是当前代码能力，不据此声称所有最新改动均已部署。

# 技术与架构亮点

- 执行内核与产品编排分层：Runtime 负责运行生命周期、调度和持久化，Desktop 负责任务拆解、协作策略与交互；当前是单进程可嵌入内核，不描述为分布式调度平台。
- 故障恢复是记录对账，不是断点续跑：将已持久化的工具结果补入模型可见记录，未完成操作标记为中断；数据库提交结果不明时通过检查点标识核验，仍不确定则停止推进，不自动重试可能已生效的操作。
- 对会话所有权、工具调度、取消与关闭过程设置边界，并以故障注入和并发测试覆盖关键路径；不把测试配置写成实际性能或覆盖率结果。
- 桌面端通过 ACP 接入 Agent、MCP 接入工具，当前 ACP Peer 在进程内运行，不声称每个 Agent 都有独立进程。审批支持 auto / request 模式，不声称所有本地工具默认必须人工批准，也不将工具目录限制称为系统沙箱。
- 招聘评分规则约束的是评价过程与可核查性，没有已验证的准确率、公平性或效率提升百分比；自然语言筛选结合工具调用与结构化过滤，不声称使用了向量检索或 RAG。
- 桌面工作台目前是早期 Alpha，线上协作服务为已部署的 MVP，Runtime 是未发布到 npm 的内部执行底座。源码中的最新能力与已交付测试包、已部署服务版本不必然完全一致，不描述为成熟生产产品。
