# 公司与方向

42 是一家聚焦视障辅助、宠物智能与阿尔茨海默照护赛道的 AI 硬件初创公司。这段工作为 Beijing · Remote；我负责全栈开发与产品交付，工作围绕人才招聘、分布式成员活动，以及团队安全、持续地使用 Agent 三类场景展开。

# 我的角色

我担任全栈开发工程师 / 负责人，负责从需求拆解、产品与架构决策到工程实现和部署。相关产出包括招聘运营后台、双语品牌与申请体验、社群活动平台，以及桌面 Agent 工作台和线上协作服务。

# 解决的问题与产出

- 招聘运营：面向候选人材料分散、初筛与检索依赖人工的问题，从 0 到 1 上线招聘后台，将材料收集、批量导入与去重、自动分析与分层评分、自然语言搜索和流程推进整合为同一工作流，并按 Admin、Recruiter、Viewer 三类内部角色提供权限。
- 候选人入口：完成双语品牌与招聘申请体验，并与已上线招聘后台完成接口联调，形成从公司介绍、材料提交到候选人评估的完整链路；新版入口尚未上线公司主域名。
- 社群活动：面向分布式成员跨城、可用时间难协调的问题，上线活动运营 MVP，自动汇总城市分布与日期交集，并支持成员与访客身份、活动配置和报名管理。
- 团队协作：完成可安装的桌面 Agent 工作台早期 Alpha 及已部署的协作服务 MVP，把多 Agent 任务协作、组织沟通、模型权限和本地工具人工审批整合为一体，并交付 macOS 与 Windows 测试包。

# 实现方式

- `42-admin` 负责候选人申请、批量导入、材料分析、自然语言检索、标签、状态流转、异步任务、权限与审计，并配套 13 页团队使用文档。
- `42` 提供双语公司叙事与招聘申请体验；`42-meeting` 负责成员资料、地点与日期决策、活动配置和报名管理。
- `42-agent` 将一次性模型调用封装为可持久化、取消和恢复的执行单元，并作为桌面工作台的统一执行底座。
- `42-agent-desktop` 负责多 Agent 编排、本地执行与人工审批；`42-agent-service` 负责账号、组织、消息和集中模型权限。

# 技术与架构亮点

- 将 Agent 执行核心与产品级编排分层：Runtime 负责确定性的生命周期与持久化，Desktop / 业务系统负责任务拆解、协作策略和 UI。
- 通过 ACP 连接编排层与独立 Agent，通过 MCP 接入外部工具；在主进程、服务端权限和显式审批之间建立安全边界。
- 同一 Agent 内按 FIFO 保证执行顺序，不同 Agent / Session 可并发；在模型和工具边界持久化检查点，降低崩溃后重复执行外部操作的风险。
- 桌面工作台目前是早期 Alpha，不描述为成熟生产产品；线上协作服务为已部署的 MVP；Agent Runtime 是内部执行底座，未作为 npm 包发布。
