# 项目概述

这是一个面向 TikTok Shop 商家的 AI 达人营销运营平台。它把达人筛选、建联沟通、样品管理、活动执行、内容分析和后续跟进串成一套自动化工作流，帮助运营人员减少重复劳动，提高达人合作效率。

# 面试时的 1 分钟版本

我做的这个项目是一个面向 TikTok Shop 商家的企业级 SaaS 平台，核心目标是利用 AI Agent 提升达人营销的运营效率。

传统达人运营需要人工筛选达人、分析数据、发送邀约、回复消息、跟进样品和检查履约，工作量大而且流程比较分散。我们把这些能力整合到了一个系统里。

整个项目分为四个部分：Next.js 实现的运营后台、NestJS 实现的业务服务、独立的 AI Agent 服务，以及 iMessage、WhatsApp、TikTok DM 等消息渠道。

系统里设计了三类 Agent：企业侧 Agent 帮运营人员查询数据、分析达人并执行运营动作；达人侧 Agent 负责自动回复达人、推荐商品和解答活动问题；任务 Agent 负责定时筛选目标达人、批量生成个性化话术并触达。

在架构上，Agent 只负责推理和选择动作，真实数据和业务规则由后端服务管理，消息投递和定时任务通过 Redis、BullMQ 异步执行。这种拆分可以避免模型直接控制核心数据，同时也提高了任务的可靠性和扩展性。

# 技术架构

运营后台 / 外部消息渠道 → AI Agent 执行层 → NestJS 业务服务层 → PostgreSQL / Redis / 外部平台 API

- 前端：Next.js、React、TypeScript、Tailwind CSS、SWR、Zustand
- 后端：NestJS、Drizzle ORM、PostgreSQL、OpenAPI
- Agent：LLM Tool Calling、Skills、Memory、流式输出
- 异步任务：Redis、BullMQ
- 消息渠道：iMessage、WhatsApp、TikTok、Discord
- 可观测性：Langfuse、OpenTelemetry、Token Usage 统计

# 三个核心亮点

1. Agent 是真正的业务执行层，不只回答问题。它能调用工具查询店铺、商品、达人、视频和 Campaign 数据，也能创建任务、修改达人状态、发送商品 Brief 和消息。模型判断下一步，工具执行确定性的业务动作。
2. 按使用者拆分 Agent 和权限。企业侧 Agent 能接触内部经营数据；达人侧 Agent 面向外部达人，只开放商品推荐、活动查询、样品申请、转人工等有限能力。两者使用不同提示词和工具集，避免仅靠一句提示词保护内部数据。
3. 即时对话和批量任务共用同一套执行体系。系统支持运营人员实时提问、达人消息自动回复和定时批量触达。BullMQ 将批量任务拆成任务和收件人两个层级，实现削峰、重试和逐达人结果记录。

# 核心业务链路：自动触达达人

1. 运营人员创建达人触达任务。
2. 调度器定时扫描到期任务。
3. 企业侧 Agent 根据商品、活动和达人表现筛选目标。
4. 系统将每个达人拆成独立队列任务。
5. 达人侧 Agent 结合达人上下文生成个性化话术。
6. 通过相应消息渠道发送。
7. 保存消息、执行记录、Token 消耗和任务状态。
8. 失败任务根据策略自动重试。

# 项目难点

最大的难点不是接入大模型，而是控制 Agent 的边界和执行可靠性。模型输出不确定，但修改业务数据和发送消息必须确定，所以所有真实操作都被封装为有明确参数校验的 Tool，后端服务是业务事实来源。企业内部信息不能泄漏给外部达人，因此企业侧与达人侧采用不同的工具权限及提示词，外发前还增加内容检查。批量触达不能在一个请求内同步完成，因此使用 BullMQ 拆开调度、任务执行和单达人处理，实现削峰、失败重试和执行追踪。

# 不足与下一步

主要优化方向包括：把部分进程内会话状态迁移到持久化存储；加强租户和店铺级权限校验；完善消息投递幂等性和死信处理；建立 Agent 自动化评测集，评估工具选择、任务完成率和敏感信息泄漏；加强链路级监控与告警。下一阶段的重点不是单纯换更强的模型，而是继续工程化 Agent 系统的可靠性、安全性和可观测性。
